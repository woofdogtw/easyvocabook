# 單字列表顯示自他動詞對照 探索

## 動機

單字列表目前第四欄是正確率。使用者的判斷是「看正確率沒有太大意義」，
想改放**自他動詞對照**，理由很具體：

> 這樣才容易對照，不用一個一個點詳細內容就能快速看到，有助學習

所以這不是換一個統計數字，而是**把列表本身變成可以掃讀的學習介面**。
這個目的決定了後面所有設計取捨。

## 正確率：桌面留，Android 拿掉數值

兩平台的處置不同，因為排序介面不同：

| | 正確率數值 | 按正確率排序 |
|---|---|---|
| 桌面 | **保留**（第六欄） | 保留（點表頭） |
| Android | **移除** | 保留（排序循環按鈕，與欄位無關） |

Android 的排序是 WORD_ASC → WORD_DESC → RATE_ASC → RATE_DESC 的循環按鈕，
和顯示哪些欄位無關，所以拿掉數值不影響「找出我一直答錯的字」——
那個需求由排序滿足，每列再印一次 `67%` 與排序重複。

桌面則是點欄位表頭排序，欄位與排序綁在一起；六欄的空間足夠，
留著就不必在兩者間取捨。

## 現況盤點

### 桌面（`rust/src/ui/word_list.rs`）

四欄，前三欄 `Length::Fill`，第四欄固定 130px：

```
單字 | 讀音 | 詞義 | 正確率(130px)
```

表頭四欄都可點擊排序（`sort_header`）。

### Android（`ui/wordlist/WordListScreen.kt`）

每列兩行，正確率靠右：

```
單字 (讀音)
詞義                    67%
```

### 資料都已經在列表裡，不需要新查詢

| | 載入方式 | 有 `wordForms` |
|---|---|---|
| Rust `load_all` | 每筆呼叫 `load_sub_records(id)`（**N+1**） | ✅ |
| Android `listWords` | 一次 `WHERE word_id IN (...)` 批次查 | ✅ |

`transitivity`、`verb_group`、`part_of_speech` 都是 `words` 的欄位，
對照詞在 `word_forms` 的 `transitive_pair` 列——**全部現成**。

**附帶發現**：桌面的 N+1 在 1162 筆資料下是 1162×3 次子查詢。
本 change 不需要碰它（資料本來就載了），但值得記錄。

## 決策

### ① 徽章內容：由「決定對照欄是什麼」的分類決定

| | 徽章 | 對照欄 |
|---|---|---|
| ja 動詞 | 自 / 他 / 自他 | 相反的那一邊（`transitive_pair`） |
| ja い形容詞 | い | 否定 or 過去 |
| ja な形容詞 | な | 否定 |
| ja 名詞 | 名 | — |
| en 動詞 | 動 | 過去式 |
| en 名詞 | 名 | 複數 |
| en 形容詞 | 形 | 比較級 |

實作規則一句話：**日文動詞取 `transitivity`（未填則退回詞性），其餘取 `part_of_speech`**。

### ② 對照欄放什麼：「必須另外背的搭檔形式」

這是「自他動詞對照」的一般化。用這個定義，英文的答案自然浮出來——
不是反義詞，是**不規則變化**：`go → went`、`child → children`。

因為徽章已經顯示分類，對照欄放什麼是**可推導的**，
不必逐列再標一次「過去式」「複數」，整欄掃下來乾淨一致。

### ③ 反義詞不做

不是因為「多個很麻煩」——`word_forms` 是多列表，三個反義詞就是三列，資料模型沒問題。

真正的理由是**它不服務對照這個目的**：反義詞沒有「兩邊互為搭檔」的對稱性，
掃過去無法形成對照，只是一堆額外的字。

⚠️ 而且有個陷阱：`word_forms` 的每一列都是**測驗的填答欄位**。
把 `antonym` 加進 canonical labels，它會自動變成必答必對的題目，
而多個反義詞時「哪個才對」根本無法定義。反義詞若只是要顯示，就不該是 `word_form`。

### ④ 徽章放在單字旁，不放在對照詞旁

使用者自己點出的問題：`自 → 上げる` 裡的「自」看起來像在描述 `上げる`。

**用位置解決**——徽章緊貼它描述的單字，對照詞在另一端，中間隔著讀音與詞義：

```
單字     讀音      詞義     自他   對照      正確率
上がる   あがる    上升     自     上げる    67%
上げる   あげる    提高     他     上がる    —
開きます ひらきます 打開     自他   開ける    80%
食べる   たべる    吃       他     —         50%
```

距離本身宣告了歸屬，不需要額外說明。而且**沒有對照詞時（食べる）依然看得到它是他動詞**，
補上了使用者擔心的缺口。

反過來，「在對照詞前面加標籤」的寫法（`他: 上げる`）在有對照時清楚，
卻**恰好在沒對照時失效**——而那正是它要工作的情境。

### ⑤ 空值顯示 `—`

沿用 `verb-transitivity` 已拍板的慣例。

## 已定案（原未決問題）

### A. 桌面加兩欄，保留正確率；排序鍵是對照詞

桌面**不與手機版面一致**——兩者形態本來就不同（表格 vs 列表）。
桌面從四欄變六欄，正確率**留下**：

```
單字(Fill) 讀音(Fill) 詞義(Fill) 徽章(~60px) 對照(Fill) 正確率(130px)
```

徽章最多兩字（`自他`），固定窄欄即可。六欄都可點擊排序：徽章欄的排序鍵是分類本身，
對照欄的排序鍵是對照詞。

對照欄改用**較窄的固定寬**而非 `Fill`——它有 83% 的列是 `—`（名詞 773 筆無對照概念、
動詞 188 筆無搭檔），不該和單字／讀音／詞義同級瓜分可變寬度，
而被擠壓的正是最需要空間的詞義欄。對照詞多為短詞（上げる、開ける），固定寬足夠。

保留正確率欄讓「移除數值是否等於砍功能」的爭議**整個消失**：
排序入口留在原處，不必在欄位與排序之間取捨。

附帶好處：桌面目前**完全看不到詞性**，徽章補上了一直缺的資訊。

### B. Android：2×2 四格，格內可換行

```
┌──────────────────────┬────────┐
│ 單字 (讀音)      8~9  │ 徽章 1~2│
├──────────────────┬───┴────────┤
│ 詞義          6  │ 對照    4  │
└──────────────────┴────────────┘
```

上排 8:2 或 9:1，下排 6:4，每格內部可 wrap。
徽章在右上、對照在右下——兩者不相鄰，維持〈決策④〉的歸屬分離。

讀音沿用現況與單字同格（`上がる (あがる)`）。

### C. 新增 `.abbr` 字串，且徽章跟著「單字的語言」

徽章用縮寫，全稱不動。兩個約束：

**① 縮寫必須在兩個命名空間的聯集上唯一。** 徽章的值來自 `transitivity`（日文動詞）
與 `part_of_speech`（其餘），而畫面上不標示是哪一個。所以
`TRANSITIVITY_KEYS ∪ EN_POS ∪ JA_POS` 內不能有重複——最明顯的地雷是
「其他」的自然縮寫就是「他」，會與「他動詞」撞號，因此改用「其」。

**② 用哪種文字由單字的語言決定，與介面語系無關。**

```
日文單字 → 名 動 形 副 代 介 連 感 其 い な 助 助動 ／ 自 他 自他
英文單字 → N  V  Adj Adv Pron Prep Conj Interj Oth
```

所以 `go V went` 在每個語系都成立，日文列在每個語系都維持同構 CJK。

CJK 內部的**簡繁字形**仍跟著介面語系（與既有的詞性全稱一致：zh-TW `動詞`／zh-CN `动词`）。
16 個縮寫中只有 3 個有差異——**動/动、連/连、助動/助动**——兩個語系各自唯一性都成立（16/16）。
拉丁縮寫沒有字形變體，三個語系完全相同。

**英文介面下的日文單字**沿用未簡化字形（動／連／助動）——那裡的選擇不是中文正簡，
而是**日文本身的正書法**（日文寫的就是 動詞／助動詞），與現行 locale 表在英文語系
仍保留 `い形容詞` 的 `い` 是同一個道理。

曾考慮改用「介面語系」當軸（日文獨有的永遠 CJK、其餘跟語系），理由是「英文沒有對應詞」——
**但那個理由對 7 項裡的 5 項不成立**：intransitive／transitive／ambitransitive／particle／
auxiliary verb 英文都有現成名稱，只有い形容詞與な形容詞真的沒有。那 7 項真正的共同點是
「只可能出現在日文單字上」，也就是「單字的語言」這條軸本身。

代價是中文介面看英文單字會顯示 `N / V / Adj` 而非 名／動／形——但那正是英漢字典
幾十年來的標記慣例。

⚠️ 拉丁縮寫比兩個 CJK 字寬（`Interj` 最長），Class 欄寬要以它為準。

### D. 自他両用與空值

- 徽章顯示「自他」，與其他徽章一視同仁
- 沒有對照詞時對照欄顯示 `—`

**不採用「自他両用一律顯示 `—`」**。資料不支持：

```
開きます (ひらきます)  自他 → 開ける
開きます (あきます)    自他 → 開ける
つきます               自他 → つける
閉じます               自他 → （無）
```

4 個自他両用的字裡 **3 個確實登記了對照詞**。一律顯示 `—` 會隱藏真實資料。
規則統一為「有就顯示，沒有就 `—`」，不因徽章種類而異。
